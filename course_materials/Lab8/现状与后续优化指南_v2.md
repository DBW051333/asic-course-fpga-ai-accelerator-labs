## 3. 最新证据如何改变瓶颈判断

### 3.1 批量计算已持续供给，缓存等待不等于可回收周期

[event_summary.json](/home/ding/vivado_project/Lab8_optimization_trials/fc1_192_input_lutram/results/event_summary.json)中，父版和候选42样本事件一致：

| 观测 | 数值 | 判断 |
|---|---:|---|
| 所有相邻start间隔 | 172拍 | 当前模型下稳定达到设计II |
| 输入接收完到start | 首样本1拍、次样本103拍、其余108拍 | 稳态输入已提前准备好，等待计算阵列 |
| 信用耗尽 / 输出反压 | 0 / 0拍 | 当前负载无需更深结果队列 |
| core_done到输出握手 | 1拍 | 输出端无大块可消除停顿 |
| waiting_input标志 | 68拍 | 条件统计，不能全部记作损失 |
| bank_blocked标志 | 4315拍 | 大量属于计算期间正常流控，不代表缺银行导致吞吐下降 |

等待标志互相重叠，不能相加；这些结论只覆盖当前DMA与内存停顿模型，真实板上需重新观察。

在现有稠密模型和精确双输出打包下，发射下限仍为：

```text
ceil(512输入 × 128输出 / (192 DSP × 每DSP每拍2个乘积)) = 171拍
II 172→171：时间收益仅0.58%
42样本核心跨度：41×172 + 216 = 7268拍
现有总时间余项：7423−7268 = 155拍，约2.09%
```

因此，保持II和核心延迟时，即使首尾余项全被消除也不足5%。暂缓第三输入银行、更宽AXIS和更深FIFO；除非板测或更强停顿模型证明它们确实减少了计算空闲。

### 3.2 延迟尾部现在有具体分解

逐样本CSV中42样本均为：start→FC1末输出188拍，随后18拍到FC2末输出，再10拍到core_done，最后1拍交付结果。这里是末事件间隔，**不是三层相加的独占计算时间**：层间早已重叠运行。

171拍发射之外的流水、结果归并和28拍后级收尾需要逐项分析，不能把它们统称“空泡”。若单样本核心要减少5%，必须从216降到≤205拍；若II不变，减11拍尾延迟对42样本总时间仅约0.15%。

### 3.3 资源热点已转移

最新[层级资源报告](/home/ding/vivado_project/Lab8_optimization_trials/fc1_192_input_lutram/results/utilization_hierarchical.rpt)显示：

| 部分 | LUT | FF | 说明 |
|---|---:|---:|---|
| FC1整体 | 8453 | 15096 | 含以下六棵树，不与树重复加总 |
| 六棵64输入加法树 | 6667 | 6768 | 占整机LUT约45.5%、FF约27.8% |
| FC2 | 1805 | 3904 | 16个DSP，已与前后级流水 |
| FC3 | 167 | 285 | 4个DSP，单独优化空间很小 |

已完成的固定权重位宽分析最多缩窄410个树寄存器位：原父版分母下1.26%，以新候选24344 FF为分母也只有1.68%。继续暂停该具体路线；这不否定改变树的寄存位置或结构可能有更大收益。

### P1：优先试加法树寄存位置重组，保持外部延迟

这是本指南新增的结构假设，**尚未综合或实现**。依据为当前 `rtl/core/adder_tree64.v`：每棵树六级寄存器分别为：

```text
32×17 + 16×18 + 8×19 + 4×20 + 2×21 + 1×22 = 1128 FF
六棵合计6768 FF
```

首选原型：将前两级加法放入同一拍，取消32×17位的第一级寄存器，保留第二级18位结果寄存器；在22位最终和之后补一个CE控制的寄存级，使树的外部延迟仍为六个有效CE拍。

```text
单棵理论净节省 = 32×17 − 22 = 522 FF
六棵理论净节省 = 3132 FF，占当前整机24344 FF的12.87%
理想算术目标 = 24344 − 3132 = 21212 FF
```

该数值是RTL寄存位预算，不是最终资源承诺。与逐节点缩位宽不同，它利用前段宽、末段窄的特点搬移寄存边界；保持完整算术位宽，不修改权重、DSP打包或量化。

先保持外部六拍延迟，是为了让现有weight/tag/valid、局部累加、snapshot和跨样本结果归并的契约不变。必须证明在任意CE暂停序列下，结果对应相同的有效输入次序；不能只在CE恒为1时比较。保留乘法器DSP内部流水，不把DSP的MREG/PREG当成可顺手删除的树寄存器。

主要风险是单拍串联两级加法后7 ns时序不通过，或工具重新平衡/复制寄存器抵消节省。综合后检查实际结构，再以包含乘积输出到树、树到累加的FC1原型评估时序；只有孤立加法树通过并不足够。

执行门槛建议：

1. 在独立目录构造原树与新树的等价对照，覆盖signed极值、随机输入、随机CE暂停及连续有效拍；计数以有效CE拍为准。
2. 同配置综合对比，确认净FF节省预期≥1218、DSP仍192/整机212，LUT/BRAM增幅受控；再做包含FC1上下游的原型实现。
3. 只有小原型有时序和净资源证据，才接入完整AXIS/DMA工程；全系统保持7 ns、216核心拍、172 II、42样本7423拍无退化。
4. 完整实现若FF达到≤23126，同时报告LUT、Slice和时序。建议Slice不增加、LUT增长不超过3%作为首轮预算；超过则重新审视收益，不隐藏代价。

若第一原型可行，第二个可选结构是每两级加法共用一拍，在窄输出端补三拍保持外部六拍：理论净少4032 FF（16.56%）。首轮不同时堆叠位宽改动、DMA修改、提频或CE细化；一个保守原型已达目标时，不必追逐更激进结构。

若选择不补回输出拍而缩短延迟，属于后续独立变体，必须修改tag/valid和所有依赖，并重新测核心周期。减1～3拍本身达不到5%核心时间门槛，不能将资源方案宣传成显著加速。

AMD说明流水深度与时序、延迟互相制约，并要求周边逻辑匹配改变的延迟；本文的3132 FF推导是针对本工程的假设，需本机Vivado 2025.2验证。[AMD UG949：流水考虑](https://docs.amd.com/r/en-US/ug949-vivado-design-methodology/Pipelining-Considerations)。DSP运算部分继续保留适当内部流水。[AMD UG949：DSP与算术推断](https://docs.amd.com/r/2024.1-English/ug949-vivado-design-methodology/Coding-for-Optimal-DSP-and-Arithmetic-Inference)。

### P2：软件优化由真实占比决定

驱动已做缓冲复用、整批DMA和分段测量，不再把这些写成待开发收益。板测若显示数据转换/复制、接收区处理、MMIO轮询、结果解析占比显著，再选择一个热点：预打包/直接填充DMA缓冲、避免重复类型转换、降低无效轮询或选择合适批量大小。

用 `总时间减少率 = 可优化部分占比 × 该部分减少率`估算。例如打包占20%、预计打包减半，才有约10%整体潜力；占3%的部分完全消除也达不到5%。冷启动不与稳态混比，异步/中断/原生驱动/SG DMA只有在测量证明需要时再引入。保留缓存一致性、超时、短包检查和恢复协议。

### P3：单样本延迟研究，先做可行性模型

输入64拍接收与FC1计算重叠仍可研究，但当前输入按chunk和输出对的访问顺序会反复读取，不能只提前拉start。建立输入到达、可读chunk、部分和存活数量、输出突发、FC2消费和异常回滚的逐拍模型。

利用最新188/18/10拍末事件分解，定位至少11拍可安全消除的核心路径，或证明API/首输入到输出窗口有≥5%收益，再进入RTL。新增部分和或更复杂缓存需要资源预算，FC1不扩大、DSP总量仍受220上限约束。

目前没有证据证明这一路必然值得完整实现；不能因P1结束就自动进入大规模调度重写。

### 条件方向：DMA时序、统一频率与能量

最新最差路径已经转到DMA S2MM DRE字节计数到零判断：13级逻辑、数据路径6.940 ns、最终WNS +0.031 ns。第二条报告路径又涉及DMA的TKEEP到NPU接收计数控制。不能继续只盯旧版输入FIFO路径，也不能认为处理一条路径就必然可提频。

保持7 ns时，降低这类路径延迟是实现稳健性工作，不是推理速度收益。关闭DRE可作为显著方案必要的时序修复选项，但历史约602 LUT节省仅相当于当前候选4.11%的量级估算，仍未证明独立达标；并且不是当前候选的实测差值。必须保证缓冲起始地址满足流宽对齐、保留1字节标量结果/162字节特征及TKEEP语义，不能把地址对齐误写为所有有效长度都要补到8字节。[AMD PG021：Simple DMA与对齐要求](https://docs.amd.com/r/en-US/pg021_axi_dma/Direct-Register-Mode-Simple-DMA)。

若后续明确选择统一提频，时间减5%要求周期≤6.65 ns，频率≥150.376 MHz；150 MHz仅减约4.76%。需验证时钟源实际可配置值、NPU/DMA/互连全部时序、硬件频率寄存器、驱动和DMA实测窗口。默认仍为7 ns，不能自动引入双域来凑门槛；历史统一6.5 ns失败与双域高Slice成本均保留为参考。

细粒度CE以真实负载下每样本能量为目标。连续批量中FC1高度活跃，空闲态优化收益不能外推；新增CE分发也可能恶化布线。无活动或板测依据时，不承诺5%节能。

## 5. 新一轮必须使用新的比较分母

以后从LUTRAM候选派生的实验，主收益相对该候选计算，不能再用旧批量版的19969 LUT/32608 FF计入已完成缓存收益。

| 主指标 | 最新候选 | 至少减少5%的整数门槛 |
|---|---:|---:|
| LUT | 14653 | ≤13920，减≥733 |
| FF | 24344 | ≤23126，减≥1218 |
| Slice | 6462 | ≤6138，减≥324 |
| 核心周期，同频 | 216 | ≤205，减≥11 |
| 42样本DMA总周期，同口径 | 7423 | ≤7051，减≥372 |

本文以`1−新值/父值`计算减少率；吞吐增加率另外报告。对指定128基线的长期对比附列，保持源基线身份，但不与直接父候选比较混成一个百分比。API时间和能量门槛待父候选实测后确定。

建议每次只选一个主指标、最多两个小原型和一条完整集成路线。分析若没有≥5%的保守预期就止损；已获显著收益证据的方案，必要集成和时序修复继续完成，说明追加投入原因。这些是建议预算，并非新授权边界。
