## 3. 先算收益上限，防止投入错误方向

### 3.1 固定192路和现有精确双输出打包的吞吐上限

FC1为512输入×128输出；当前每个DSP每拍处理共享输入的两个输出权重乘积。保持相同稠密计算与打包方式时：

```text
FC1发射下限 = ceil(512 × 128 / (192 × 2)) = 171拍
当前发射 = 171拍；当前启动间隔 = 172拍
仅消除启动间隔的1拍：时间降低 1/172 = 0.58%
```

这不是所有可能算法的绝对下限：若能证明精确稀疏跳过或新的运算编码，可另算。但在当前算法内，不能承诺靠“进一步精密调度”把II降到150拍。

对当前42样本仿真，按无停顿核心跨度估算：

```text
41 × 172 + 216 = 7268拍
7423 - 7268 = 155拍，占2.09%
```

155拍是首尾搬运、启动及模型停顿等的合计余项，不是可全部消除的DMA浪费。即便消除该余项，固定II和核心延迟也达不到5%总时间收益。更宽AXIS、更多缓存银行、更多结果信用，均须先证明现有等待足够大。

### 3.2 将“5%”换成验收数字

本文默认用**时间减少率** `1 - T_new/T_parent`；吞吐增加率 `T_parent/T_new - 1`另列，不能混用。

| 主指标 | 当前比较对象 | 至少5%减少的门槛 |
|---|---:|---:|
| 核心周期，同频 | 216拍 | ≤205拍，至少减11拍 |
| 稳态II，同频 | 172拍 | ≤163拍；当前稠密架构无法仅靠去气泡实现 |
| 42样本DMA仿真，同口径 | 7423拍 | ≤7051拍，至少减372拍 |
| LUT | 19969 | ≤18970，至少减999 |
| FF | 32608 | ≤30977，至少减1631 |
| Slice | 9875 | ≤9381，至少减494 |

资源优化可选FF或LUT为主指标，但必须同时报告其余资源、Slice和性能代价。局部模块减少5%不代表整机减少5%。实板API延迟和能量先测父版，再计算门槛。

## 4. 优先方向与具体工作

### P0：补足测量与等待原因分解，为后续立项提供依据

这是决策基础工作，不将新增计数器或测试脚本本身计为性能优化。

**软件计时须纠正口径。** 当前 `ps/lab8_driver.py` 的 `ps_end_to_end_us` 从 `_exchange()`启动收发DMA前计到等待完成后；输入检查、转换、打包、接收区清零、结果复制解析及之后的统计寄存器读取在窗口之外。后续报告保留旧字段兼容，同时明确称其为“主机DMA调用窗口”；额外记录整个 `infer()`/`infer_batch()` 的API墙钟时间，不能沿用字段名宣称完整应用延迟。

先用现有 `ps/run_batch.py` 做板上功能和标量/批量对照，再在独立脚本扩展：

- 批量大小N=1、3、8、16、42、48、128；同一输入和相同精度。较大批量报告等待凑批成本，不以吞吐掩盖交互延迟。
- 预热、复用缓冲、至少100次重复，报告中位数/P95及测量波动；冷启动、分配、特征读取单列。
- 分离API总时间、打包/拷贝、DMA调用窗口、结果解析、PL事务周期、核心周期。软件分段测量注意自身开销；PL与PS窗口并非相同边界，不直接相减后命名“纯Python时间”。
- 比较双方使用同一bit/hwh、输入、时钟与测试环境；保存部署包哈希、板卡与软件版本。
- 无板卡时完成仿真事件追踪和板测脚本，记录“未上板”，不要制造测量结果。

仿真至少记录每个样本的输入完成、start、FC1末输出、FC2末输出、core_done、输出握手时间；区分等待输入、FC1忙、银行占用、结果信用耗尽、输出反压。让每个“瓶颈”有事件数据支持。

**进入软件优化的条件：** 拷贝、重复MMIO轮询或小批量启动等可改部分占API总时间足够大，并有保守预测≥5%。再评估预分配之外的数据直写、减少多余类型转换、批量调用策略、轮询开销；驱动已复用缓冲，不能重复计入收益。中断、原生驱动或SG DMA需先证明必要性，不默认大改软件栈。

### P1-A：重组双输入缓存，优先评估FF和选择网络成本

证据：`rtl/core/fc1_paired.v` 中64组 `word0/word1` 各64位，RTL存储量为8192位，约相当于当前整机FF数的25.1%；另有双银行选择和三个512位分块选择网络。8192是源码存储位数，实际可回收FF数量须由综合网表确认。

**建议原型：利用固定调度，把寄存器阵列改成分银行LUTRAM或BRAM存储。** 三个子阵列每拍访问连续的三个chunk，其chunk地址为 `issue_job[2:0]`。先枚举171拍完整访问轨迹，寻找无冲突的分银行/复制方案，不凭总容量判断只需一块RAM。

注意跨输出对回绕：连续chunk可能是6、7、0或7、0、1。简单 `chunk % 3` 分银行会发生冲突，必须显式处理；可比较按奇偶分银行的双读端口、选择性复制或重新安排chunk访问，并证明新顺序不引入额外发射周期。

原型需同时满足：三个512位chunk读取、64位逐拍写入、双样本银行切换、读延迟与weight/tag/valid同步、随机CE暂停、异常后恢复。BRAM读取延迟及端口宽度会改变流水和资源，不能只加 `ram_style` 属性期待自动得到最优结构。LUTRAM异步读特性见[AMD UG474](https://docs.amd.com/r/en-US/ug474_7Series_CLB/Distributed-RAM-Summary)；BRAM模式按[AMD UG473](https://docs.amd.com/v/u/en-US/ug473_7Series_Memory_Resources)和本机2025.2模板核对。

**建议立项预算（不是用户新增硬约束）：** 主目标整机FF至少减1631或Slice至少减494；期望不增加II，核心不退化；DSP仍212。先给出BRAM端口映射和块数，建议额外BRAM36等效不超过16作为首轮探索上限，LUT增长不超过5%；若代价超出，重新评估是否值得。不能用容量利用率忽略读带宽复制成本，也不能因FF下降就宣称省电。

步骤：访问轨迹和端口模型 → 小模块综合比选 → 接入完整RTL回归 → 完整实现。若端口复制/选择网络把收益吃掉，应记录失败原因并止损。

### P1-B：固定权重范围分析，减少加法树和中间结果位宽

当前 `results/utilization_hierarchical.rpt` 中六棵 `adder_tree64` 合计 **6667 LUT、6768 FF**，约为整机LUT的33.4%、FF的20.8%。每棵采用16位乘积、逐级增长至22位，再扩展输出。

从实际重排权重出发，对每个lane、发射位置、树节点和累加阶段计算所有合法INT8输入的保守上下界；若多个时隙共享一个节点，取这些时隙界限的并集。先分别证明低/高乘积分离及符号修正，再证明可缩窄位宽。不能用42样本观测最大值代替全输入范围证明，也不能只检查最终ReLU结果。

现有FC1累加已是23位，已有固定权重保守绝对界3205146；这并不自动证明整个累加器可降到22位有符号数。新证明必须覆盖各局部和、中间相加及bias。

若希望仅靠这些树实现整机LUT减少5%，局部需要约15%净节省；整机FF减少5%则约需树内24.1%净节省。先跑静态位宽分析并做小模块综合，若达不到整机门槛，暂停全面改造。所有运算乘法仍DSP，避免不规则宽度导致综合退回LUT或破坏DSP打包。

这是资源优先实验；减小面积、扇出或布线距离可能有助时序，但不能在实际实现前承诺频率提升。

### P2：针对单样本的输入接收与计算重叠、尾部流水优化

仅在需求明确偏向N=1或小批量，且周期模型预计同口径收益≥5%时进入。

当前完整接收64个64位输入拍后启动FC1。可研究输入分块到达后开始计算，或更紧凑的FC1结果归并、FC2/FC3收尾。必须绘制逐拍依赖图：输入chunk何时可读、哪些输出部分和存活、权重顺序、FC2消费能力、结果输出排队。

当前调度面向输出对，过早启动会访问尚未到达的数据；切成输入块优先会增加在途部分和，并可能把FC1输出集中到尾部。保留FC1规模和剩余8 DSP限制，不能假定FC2能无限扩宽，也不能去掉必要DSP寄存器来减少表面周期。

核心216拍比171拍发射多45拍，**这45拍不是可无损全部删除的等待**，包括必要读取、运算流水和后级处理。先识别至少11拍可安全去除的依赖，再做核心延迟实验。提前开始若改变核心统计窗口，应比较输入首拍到结果握手及API总时间，不能用重新定义start来虚增收益。

批量II保持172时，减少11拍尾延迟对42样本总时间只贡献约0.15%；不得当作5%批量加速。

### P3：输入控制本地流水、控制扇出与物理布局

当前最差路径在 `results/critical_paths.rpt`：DMA数据寄存器 → 输入包长度/末拍判断 → 输入FIFO写指针CE，9级逻辑，数据路径6.614 ns，其中布线4.288 ns。优先查这条路径，而非假定乘法器是当前时序瓶颈。

历史 `fc1_192_ingress_pipeline` 中弹性输入寄存器、提前寄存写使能、去即时信用旁路可作为设计参考，但不直接复制整版。任何移植从当前单时钟版独立派生，保留TKEEP/TLAST、异常帧、反压稳定性和软复位语义，并重新验证。

在7 ns下仅改善WNS不计作推理速度收益；可作为P1资源优化或P2流水方案的必要时序收敛工作。单独提频实验属于后续选项：同周期数时间减5%要求周期≤6.65 ns，且必须NPU/DMA/互连一起通过。历史统一6.5 ns已失败（WNS −0.198 ns），没有新结构证据不重复跑。

不得通过虚假false path、无依据multicycle或只约束NPU来“修好”完整系统。setup、hold、时钟与DRC均需在保存的最终DCP复核。

### P4：有效位驱动的细粒度时钟使能与能量评估

当前只有任务级CE，README明确尚未按流水级valid细化。可评估空闲阶段ROM、DSP输入寄存器和加法树的CE；采用同步使能，不能直接组合门控时钟。DSP内部寄存器及CE定义见[AMD DSP48E1文档](https://docs.amd.com/r/2021.2-English/ug953-vivado-7series-libraries/DSP48E1)。

它更可能对间歇负载有效，连续批量下乘法阵列接近满负荷。须同时对比空闲、真实业务占空比、连续批量；以每样本能量或同负载平均功率为主指标。匹配活动率的布线功耗估计只能作为估计，板上整板功率与PL动态估计分列。预计不能达到5%就暂缓，避免增加CE扇出而损害时序。

## 6. 每次实验的执行与预算

建议一次只验证一个主假设。以下是推荐工作预算，不冒充用户要求：

1. **分析阶段：** 先用不超过半个工作日完成上限估计、周期/端口模型和资源预算。达不到5%就写止损记录，不启动昂贵实现。
2. **小原型阶段：** 最多比较两个结构候选，先验证整数结果、握手及小模块综合。一次物理时序失败不能证明结构无效，但要找到具体路径原因。

## 7. 不可省略的验证与交付
