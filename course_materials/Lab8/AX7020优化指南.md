## 3. 最新结果改变了优化重点

从原始 100 次结果抽取各阶段中位数：

| 模式 | 输入检查/分配/打包 μs | 接收清零 μs | 主机 DMA 调用窗口 μs | 解析/统计 μs |
|---|---:|---:|---:|---:|
| scalar N=1 | 686.166 | 17.859 | 926.134 | 102.958 |
| batch N=42 | 1411.872 | 20.910 | 936.695 | 855.859 |
| batch N=128 | 2710.985 | 25.218 | 1037.031 | 935.252 |

这些是分段中位数，不能相加当成整体中位数，也不是无遗漏的调用剖析。主机 DMA 窗口含软件启动、轮询和缓存处理，不能视为纯 DDR 搬运时间；它与 PL 计数边界不同，不能相减后给差值命名为某种确定开销。驱动兼容字段 `ps_end_to_end_us` 仍表示这个 DMA 调用窗口，`api_wall_us` 才用于完整 API 对比。

**当前证据支持先优化软件调用路径，具体函数热点还需分解测量。** batch N=42 的 PL 事务约 51.359 μs，只相当于完整 API 时间的 1.55%；即便假设这整个区间可被消除且其他部分不变，端到端收益量级仍低于 5%。该比例只用于判断投入优先级，不能用作精确的可加时间模型。单样本核心 1.512 μs 相对 1832.430 μs 的 API 更小，单独省几拍不会解决当前毫秒级调用开销。

固定 FC1 192 路时，512 个 64 输入配对任务每拍最多发射三个，至少需要 171 个发射拍。现有 II=172 接近该结构下限；压至 171 的吞吐窗口时间收益仅约 0.58%。在新 AX7020 等待证据出现前，不优先加第三输入银行、加深 FIFO 或扩宽 AXIS。

## 4. 下一轮工作顺序

### P0：锁定可重复的 AX7020 软件对照

保留当前 bit/hwh 和驱动为 A，独立目录派生软件候选 B。先在同一块 AX7020 复测 A，再轮换 A/B 顺序，固定输入、N、接口语义、缓存策略和计时边界。记录板卡身份、CPU 频率/调度环境、系统负载、Python/PYNQ/NumPy 版本及文件哈希；不把历史单次测试当作永久精确常数。

复用 [benchmark_api.py](/home/ding/vivado_project/Lab8_AX7020_192/ps/benchmark_api.py)，补充最小的热点计时：输入类型/范围检查、转换、DMA 缓冲写入、DMA 启动、等待及缓存处理、结果拷贝、响应检查、寄存器读取。细分计时用于归因，最终 A/B 使用相同外层计时，避免插桩本身污染结论。

本轮建议以 **batch N=42 的完整 API 中位数减少至少 5%** 为主指标，同时报告 scalar N=1、batch N=128 与全部已测批量点的 P95。若应用明确偏向单样本，立项时换主指标，不在结果出来后挑最好看的 N。

### P1：输入检查与打包路径，优先小改动验证

[lab8_driver.py](/home/ding/vivado_project/Lab8_AX7020_192/ps/lab8_driver.py) 每次做范围检查、`astype(np.int8)` 和 DMA 缓冲复制。优先测试以下有具体依据的候选：

- 对已经是合法 shape 的 `int8` 数组，保留类型/形状检查后，评估跳过必然成立的范围扫描及避免重复 `astype` 分配；其他整数类型仍检查范围，浮点、越界和错误形状继续拒绝。
- 比较批量连续拷贝与现有缓冲切片赋值的实际开销，核查缓存一致性和 ndarray/PynqBuffer 行为；预打包或直接填充缓冲需明确输入所有权、生命周期和更新规则。
- 对响应解析中的临时数组、重复拷贝做微基准，再决定是否减少拷贝；返回结果必须在下一次推理覆盖接收缓冲后仍保持正确，不能默默返回易失视图。

N=42 输入阶段占 API 的约 42.5%。按分段近似估计，若该阶段减少 20%，整体有约 8.5% 的改善空间；这是立项估计，只有板上完整 A/B 才能证明。N=128 输入阶段更大，需同时检查收益是否随 N 延续。

缓冲复用、整批 DMA 和分段计时已存在，不再当作待开发功能。预打包把工作移到计时外时，应另外报告“原始输入到最终结果”的总时间；可复用输入场景才另报摊销收益。

### P2：响应解析、统计和 DMA 调用开销

batch N=42 解析/统计约 856 μs，DMA 调用窗口约 937 μs，均值得进一步拆解，但不能预先断言 MMIO 或轮询独占这些时间。

优先保持 API 返回字段和校验语义，减少重复工作。若需要新增轻量接口或可选详细统计，明确这是接口变体，同时给出完整接口对照；不以删除正确性检查、超时、错误恢复、实际接收长度检查或 cache 同步制造“加速”。

当前 `_wait_dma()` 在轮询中检查两路错误/idle，完成后调用 PYNQ `wait()` 做接收缓存无效化和实际长度记录。优化时不得仅以 idle 为由跳过必要的完成处理。中断、原生扩展或直接寄存器驱动只有在分析显示可带来至少 5% 完整 API 收益时再立项，先预算开发和恢复逻辑成本。

接收清零当前约 18–25 μs，占总时间不足 1%；单独删除清零不作为主线。扩容后 `_exchange()` 清零整个接收缓冲，若引入更大常驻容量，应专门评估“小 N 使用大容量缓冲”的额外成本和有效长度语义。

### P3：按应用目标选批量大小，补充持续运行证据

保留 N=1 的低延迟 scalar 路径，对已有输入集合优先使用批量。下一批量扫描可从 N=256/512 等有限规模开始，先确认 CMA、分配失败清理、地址覆盖及实际传输长度；最大 16383 是协议/23 bit DMA 长度约束，不是已验证工作点或必须追求的默认容量。

报告完整批量总时间、样本吞吐、P95，以及在线输入的凑批等待。固定间隔到达的近似模型为首样本等待 `(N−1)×间隔`、平均等待约一半；这只是应用假设，真实到达流另测。选使业务延迟与吞吐达标的 N，不以最大吞吐自动覆盖单样本需求。

增加长时间连续推理、批量大小切换、扩容/复用、异常后继续运行。把 N>42 的数据标注为重复负载。可靠性验证是交付范围，不作为性能收益凑数。

### 条件方向：PL 资源、统一提频与能量

后续 PL 优化应有独立主指标，不能承诺相同幅度的 API 加速：

- **资源优化：** 以当前 AX7020 的 14299 LUT、18905 FF、5791 Slice 为分母重新分析热点；输入 LUTRAM、加法树寄存重组、FC2 单套累加已集成，不能重复计收益。新方案先做结构/端口/范围证明和小原型，再完整实现。
- **控制路径：** 最新 [critical_paths.rpt](/home/ding/vivado_project/Lab8_AX7020_192/results/critical_paths.rpt) 最差路径是 FC2 `first_pipe_reg[4]_rep` 到单累加器，数据延迟 6.844 ns，其中布线 5.768 ns、占 84.28%，控制网扇出 180。后续时序修复应从当前路径出发，不能套用旧版“DMA 输入判断最差”的结论。固定 7 ns 下改善 WNS 是裕量改善，不是推理加速。
- **统一提频：** 同周期数下 PL 时间至少减 5%，需周期≤6.65 ns，即频率≥150.376 MHz；150 MHz 只减约 4.76%。当前 +0.229 ns WNS 不证明该目标可过。现用约 1 GHz IO PLL 配 7 分频产生约 142.857 MHz，频率配置是离散的；先核查可实现的统一频率和相关时钟假设，不能盲写 PYNQ 时钟属性。历史 Z2 6.5 ns 失败不证明 AX7020 -2 必败，但当前软件瓶颈也不支持优先投入提频。
- **能量：** 有实际负载和测量条件时，比较空闲、业务占空比、连续批量的整板功率与每样本能量。LUT/FF 下降及默认活动率功耗报告都不能替代实测；细粒度同步 CE 仅在收益预算成立时探索。

继续保持单 PL 时钟，FC1 192 路，所有新乘法使用 DSP。不得用 LUT 补乘法或扩大 FC1 来达到指标；不得用不真实的时序例外换取时序通过。

## 6. 收益门槛与建议预算

时间/资源减少率为 `(父版−候选)/父版`；吞吐增加率为 `候选/父版−1`。两者分开写，不能把加速倍数直接当时间减少百分比。

以下仅用当前数据给出 5% 减少的立项参照；最终采用同板同轮 A/B 的父版数据计算：

| batch N=42 完整 API 中位数 | 3319.907 μs | ≤3153.912 μs |
| batch N=128 完整 API 中位数 | 4834.145 μs | ≤4592.438 μs |

| FF | 18905 | ≤17959，至少省 946 |

建议首轮只选择一个主假设：先用半个工作日以内完成剖析和上限估计，最多两个软件小原型；软件优化沿用已验收 bit/hwh，优先完成板上 A/B。没有至少 5% 的合理预期就记录止损，暂缓完整实现。

## 7. AX7020 平台要点与回归

### 保持已跑通的平台配置

当前使用 `alinx.com:ac7020:part0:1.0` 社区 PS 预设，PS 参考 33.333333 MHz、32 位 1 GiB DDR、UART1。两路 DMA 都覆盖 `0x00000000–0x3FFFFFFF`，每次核对完整缓冲区地址范围。实际容量/CMA 以运行系统为准，不写死历史分配地址。
