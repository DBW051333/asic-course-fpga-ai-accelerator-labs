## 4. 移植步骤

### 4.1 建立独立副本并记录来源

复制源码、模型、PS 程序、testbench、约束与工具。重新生成 Vivado 工程，不把来源的生成目录和旧 bitstream 当作新结果。旧报告如保留，放入 `evidence/source/`；新 `results/` 仅记录本工程运行结果。

增加 `migration.json`，至少记录：目标工程 ID、直接父工程路径、源基线 ID、目标板卡、Vivado 版本、时钟目标、模型哈希、改动清单及各阶段验证状态。

搜索并修正文本中的来源绝对路径，重点检查 RTL 的初始化文件、testbench 数据路径和 Python/Tcl 脚本。模型数据只改引用路径，保持数值文件哈希一致。不要对二进制或历史证据执行全目录字符串替换。

保持 FC1 192 路、重新量化模型、全 DSP 乘法及单 PL 时钟；移植阶段先解决板卡适配和验证。

### 4.2 修改硬件构建入口

以来源 `tools/build.tcl` 为主，参考 smoke 的 PS 自动配置方法：

```tcl
set_param board.repoPaths [list /home/ding/vivado_boards/ax7020_board_files/board_files]
create_project Lab8 $root/vivado -part xc7z020clg400-2 -force
set_property board_part alinx.com:ac7020:part0:1.0 [current_project]
```

先应用 AX7020/AC7020 PS preset，再启用 Lab8 所需的 GP0、HP0、中断与 FCLK0。不能仅改 part 而保留 Z2 的 PS preset。

保留来源的互连拓扑：

- PS `M_AXI_GP0` → 控制互连 → DMA `S_AXI_LITE` 与 `npu_0/S_AXI`。
- DMA `M_AXI_MM2S`、`M_AXI_S2MM` → 内存互连 → PS `S_AXI_HP0`。
- DMA `M_AXIS_MM2S` → NPU `S_AXIS`；NPU `M_AXIS` → DMA `S_AXIS_S2MM`。
- NPU、DMA、控制/内存互连及 GP0/HP0 ACLK 共用 FCLK0。
- FCLK_RESET0_N 经 `proc_sys_reset` 分别提供互连和外设复位；BD 验证后检查实际复位极性。

保留 DMA：simple mode（SG 关闭）、32 位地址、64 位内存和流接口、双向 DRE、burst 16、长度宽度 23 bit。保持实例名 `axi_dma_0` 和 `npu_0`，便于复用驱动。

来源的 `control_routing.xdc` 用于限制高扇出控制网的时钟缓冲选择，并非 Z2 引脚约束；迁移后按新网表检查其匹配情况。当前仅使用 DDR/FIXED_IO，无需复制 Z2 的 LED/按键 XDC。

### 4.3 优先核查 DMA DDR 地址覆盖

这是本次已确认的具体风险：来源 HWH 中两路 DMA 的 `HP0_DDR_LOWOCM` 地址范围均为 `0x00000000–0x1FFFFFFF`，而 AX7020 smoke 分配的物理地址 `0x38100000` 超出该范围。

应用目标 PS preset 后重新 `assign_bd_address`，检查 MM2S 与 S2MM 两个主地址空间，确保覆盖目标系统允许分配的 DDR 区域。仅修改 PS 的 DDR 容量或 Linux 内存节点，不足以证明 DMA 互连地址解码已更新。

新 BD/HWH 中逐项保存地址表。板上每次记录 `physical_address` 与 `nbytes`，确认整个缓冲区都在两路 DMA 可达范围内。物理地址由分配器返回，不能写死 smoke 地址。若系统限制了内存/CMA，记录实际范围，不用“板载 1 GiB”替代运行配置。

NPU/DMA 控制地址以新 HWH 为准。来源是 NPU `0x40000000`、DMA `0x40400000`；驱动通过 Overlay 实例取 MMIO，地址改变时优先核对 HWH 配套，而非手写旧地址。

### 4.4 核查真实运行时钟

目标保持 NPU/DMA/互连统一约 142.857132 MHz（7 ns）。Vivado 使用 33.333333 MHz PS 参考时钟生成目标分频，检查实际生成频率、FCLK 源 PLL 和分频器。

已有 smoke 发现：板上 PYNQ 3.0.1 Zynq 时钟帮助类按 50 MHz 参考时钟计算，报告 75 MHz；按 AX7020 参考晶振折算为约 50 MHz。不能直接相信 `Clocks.fclk0_mhz`，也不要为“修正显示”直接写 `Clocks.fclk0_mhz = 142.857132`。

Overlay 加载后核查板上真实 PLL 和 FCLK 分频寄存器，按目标参考晶振计算。HWH 提供的分频值也需要与当前启动系统的 PLL 设置相符。Overlay 下载不会替代 FSBL 完成整套 PS/DDR 初始化；若启动系统 PLL 与新硬件假设不同，先明确差异再处理。

NPU `0x0C` 返回的是 RTL 固定常量 `142857132`，不是频率测量器；驱动读取它只能验证协议声明。必要时用 `0x30` 的自由运行 tick，在多个较长时间窗口与主机单调时钟比较，处理 32 位回绕及 MMIO 开销，作为辅助检查；精确仪器测量另记验证范围。

若目标频率无法实现，记录实际频率与原因。低频调试应建立独立配置，同步调整 RTL 接口频率声明、时序检查、驱动约束及统计字段，不能用 142.857132 MHz 换算低频结果。

## 6. 板上验收顺序

每阶段保存命令、日志、时间、板卡身份及软件/硬件哈希。前一阶段通过后进入下一阶段。

### A. Overlay 与控制寄存器

加载目标 bit/hwh，确认实例 `axi_dma_0`、`npu_0` 存在；读取 NPU `0x00 == 0x4C414238`，检查状态、软复位和两路 DMA 状态。记录真实时钟核查结果及缓冲区物理地址。

寄存器辅助定位：`0x10` 完成任务数，`0x14` 错误数，`0x18` 最近核心周期，`0x1C` 最近事务周期，`0x20/0x24` 接收/发送字节数，`0x28` 最近错误，`0x2C` 最近命令，`0x30` tick。

### B. 首个样本与逐层数值

先单样本打通 DMA，再执行全部 42 样本逐层检查。在部署目录运行：

```bash
python3 run_lab8.py --bit lab8.bit --features --output board_scalar
```

实际 SSH 运行时替换成已验证的 PYNQ 解释器。此脚本参数是 `--bit`。检查 42 个分类与独立整数参考一致、42×162=6804 个特征数值一致、完成任务数 42、错误数 0。脚本的旧 `PYNQ-Z2 board run` 描述需改为 AX7020，频率字段按核查后的真实配置记录。

### C. 批量推理

```bash
python3 run_batch.py --bitfile lab8.bit --output batch_board_results.json
```

检查 42 样本批量类别、signed scores 与参考一致，最后样本全部特征一致。继续验证 N=1/3/8/16/48/128、连续批次、重载 Overlay 和异常后恢复。大于 42 的重复样本是性能负载扩展，不是新增准确率数据集。

协议保持：CMD1 输入 520 字节、分类实际返回 1 字节；CMD2 请求 8 字节、特征实际返回 162 字节；CMD3 输入 `8+512*N` 字节、返回 `8*N` 字节。流为 64 位，小端头部，带 TKEEP/TLAST；接收缓冲区容量与实际有效字节数分别检查。批量上限 16383 来源于协议和 DMA 长度约束，已有边界检查不等于最大批量已板测。

### D. 真实 API 性能

```bash
python3 benchmark_api.py --bitfile lab8.bit --package /实际路径/lab8_ax7020_192.tar.gz --board-id AX7020_实际编号 --repeats 100 --warmup 10 --output api_board_results.json
```

记录冷启动/分配、完整 `api_wall_us`、DMA 调用窗口、中位数/P95及原始数据。旧字段 `ps_end_to_end_us` 实际是主机 DMA 调用窗口，不能当完整 API 时间；PL 周期窗口与 PS 窗口边界不同，不能简单相减归因。

216 拍、172 拍和 7423 拍用于相同模型下的仿真对照。板上 DDR 与 PS 开销可能改变事务时间；报告实际数据，不把 51.961 μs 仿真值写成板测结果。只有真实数据支持时再提出优化，遵守 AGENTS 的收益门槛及预算约定。

## 7. 故障定位

| 现象 | 优先检查 |
|---|---|
| Overlay 加载失败或实例缺失 | bit/hwh 配套、目标 part、PYNQ 解释器、FPGA manager 与日志 |
| NPU 签名错误 | 新 HWH 地址、实例名、AXI 控制连接、时钟和复位 |
| MMIO 通，DMA 超时 | HP0 是否启用、两路 DMA 地址覆盖、实际缓冲区地址、复位/时钟、DMA 错误状态 |
| DMA slave/decode error | DDR 地址解码及缓冲区末地址、HP0 连接、传输长度 |
| 接收不结束 | S2MM 先启动、TLAST/TKEEP、NPU 输出反压、命令/字节计数 |
| 分类偶发错误或读到旧数据 | flush/invalidate、缓冲区生命周期、并发事务、DMA 实际返回长度、时序 |
| 时钟显示高出约 1.5 倍 | PYNQ 的 50 MHz 参考假设与 AX7020 33.333333 MHz 差异 |
| 频率常量正确但速度异常 | `0x0C` 是常量；复核当前 PLL/FCLK 寄存器与计时边界 |

驱动已有有限超时和 DMA/NPU 恢复逻辑，保留“先挂接收、再发发送”的顺序。错误发生时先保存 DMA register_map、NPU 状态、缓冲区地址与传输长度，再恢复；不要靠无限等待或反复重试掩盖问题。
