# Lab4 并行计算规模对比报告

## 1. 目标与工程位置

本次比较全连接第一层（512 个输入、128 个输出、8 位有符号乘法、偏置与 ReLU）在 **128 路**和 **64 路**并行乘法下的面积、时序及单次计算时间。三个工程均使用器件 `xc7z020clg400-1`、Vivado 2025.2、`clk_i` 10 ns（100 MHz）约束，并用同一个 `fc1.txt` 核对 128 个输出。

| 方案 | 工程 | 说明 |
|---|---|---|
| A：128 路基线 | `/home/ding/vivado_project/Lab4_optimized/Lab4.xpr` | 此前完成的单累加器优化方案，原有 RAM 数据布局 |
| B：64 路、原 RAM 布局 | `/home/ding/vivado_project/Lab4_parallel64/Lab4.xpr` | 每个 1024 位 RAM 字分两次取用；保留原 COE 和 RAM IP |
| C：64 路、重排 RAM | `/home/ding/vivado_project/Lab4_parallel64_packed/Lab4.xpr` | RAM 改为每字 512 位；数据顺序不变，省去前后半字选择逻辑 |

原始 `/home/ding/vivado_project/Lab4/Lab4.xpr` 未修改。A、B、C 是各自独立的工程，C 是本轮较好的 64 路实现。

## 2. 测量口径

- **面积**：完整 `fc_top` 布线后的 Vivado `report_utilization`，包括 RAM 和乘法器 IP。LUT、寄存器、DSP、BRAM Tile 分开列出；不把不同资源混成单一“面积”。
- **时序**：布线后 `report_timing_summary` 的 WNS 和 WHS。三个方案的 10 ns 时钟约束均通过。
- **“最高频率”**：从这一次布线的 WNS 推算：`F估算 = 1000 / (10 - WNS)` MHz。它是**当前布线结果的静态时序估算**，没有在更短周期重新布局布线，也没有上板测频；不能当作硬件实测最高频率。
- **单次计算时间**：同一 XSim 测试平台在 10 ns 时钟下，从 `start_i` 拉高到完成 128 项输出核对的时间。测试平台在 `done_o` 后再等两个上升沿，故此数字包含相同的验收余量；它适合方案间比较，并非单纯组合逻辑延迟。A 的 `start_i` 在 60 ns，核对时刻为 5325 ns，差为 5265 ns（原日志 `$finish` 在 5345 ns，核对后还等 20 ns）；B、C 直接由测试平台打印为 10385 ns。
- 当前 XDC 只有时钟约束；外部接口尚未加入输入/输出延迟约束。所有“时序通过”和频率估算针对已约束的内部路径。

## 3. 布线后结果

| 方案 | XSim 正确输出 | LUT | 寄存器 | DSP | BRAM Tile | WNS @ 10 ns | WHS | 当前布线估算频率 | 单次计算时间 @ 100 MHz |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| A：128 路 | 128/128 | 2273 | 2944 | 128 | 29.5 | +2.602 ns | +0.018 ns | 约 135.2 MHz | 5.265 µs |
| B：64 路、原 RAM 布局 | 128/128 | 1701 | 2621 | 64 | 29.5 | +2.166 ns | +0.065 ns | 约 127.6 MHz | 10.385 µs |
| C：64 路、重排 RAM | 128/128 | 1189 | 1596 | 64 | 22.5 | +2.384 ns | +0.045 ns | 约 131.3 MHz | 10.385 µs |

与 A 相比，C 的 LUT 少 **47.7%**、寄存器少 **45.8%**、DSP 少 **50.0%**、BRAM Tile 少 **23.7%**；估算频率低约 **3.9 MHz（2.9%）**，在相同 100 MHz 时钟下单次计算时间多 **5.120 µs（97.2%）**。

B 与 C 说明 RAM 布局对结果影响很大。B 的最慢路径从控制寄存器经过半字选择到乘法器，C 去掉该选择后最慢路径回到加法树。C 比 B 少 512 个 LUT、1025 个寄存器、7 个 BRAM Tile，WNS 多 0.218 ns。

## 4. 操作过程与复现

### 操作 1：记录 A 的基线

从 `/home/ding/vivado_project/Lab4_optimized/timing_impl_final.rpt` 和 `utilization_impl_final.rpt` 记录布线后资源及 WNS、WHS；从 `optimization_report/single_accumulator/xsim_final.log` 记录 `128/128 PASS` 与仿真结束时刻。`clk_i` 的 10 ns 约束位于 `Lab4.srcs/constrs_1/new/time1.xdc`。这一操作只读 A，没有修改其 RTL。

### 操作 2：制作 B（只改并行路数，保留原 RAM）

复制 A 为独立工程 B。将 `fc.v` 的 `GROUPS` 从 4 改为 8、`group_idx` 改为 3 位；每个 1024 位输入/权重字先用高 512 位，再用低 512 位。`mult_array.v` 从 128 个 8 位乘法器改为 64 个，`adder_tree.v` 从 128 项加法树改为 64 项，并保留三个流水级。地址仍读取原来宽 1024 位的 COE/RAM。半字选择信号与同步 RAM 输出对齐到控制延迟链第 1 级。偏置、ReLU、128 项输出及参考文件不变。

先运行 `/home/ding/vivado_project/Lab4_parallel64/comparison_report/run_sim.tcl`；XSim 输出 `PASS: all 128 FC outputs match fc1.txt`。然后运行同目录的 `run_impl.tcl`，先重综合，再布局布线，导出 `timing_synth.rpt`、`utilization_synth.rpt`、`timing_impl.rpt`、`utilization_impl.rpt`。对应日志为 `sim_console.log`、`impl_console.log`。

### 操作 3：制作 C（同为 64 路，配套重排 RAM）

复制 B 为独立工程 C。运行 `/home/ding/vivado_project/Lab4_parallel64_packed/comparison_report/repack_coe.py`，把每个 1024 位 COE 数据字按“高 512 位、低 512 位”拆成相邻的两个 512 位字；脚本逐行验证重新拼接后与原字逐位一致。输入 RAM 从 `1024×4` 改为 `512×8`，权重 RAM 从 `1024×512` 改为 `512×1024`，使用新生成的 `sel_data_64.coe` 和 `fc1.0.weight_64.coe`。`fc.v` 的地址按 8 组顺序生成，去掉 B 中的半字选择。RAM IP 的变更记录在 `configure_ram.tcl`；当时额外尝试用 `save_project_as` 保存到已经打开的同一路径，Vivado 报“project already open”，但此前的 IP 参数和生成结果已写入 XCI，随后仿真、综合和布线均成功。可复现脚本已删掉这条多余命令。

先运行 C 的 `comparison_report/run_sim.tcl`，XSim 输出 `128/128 PASS`、`start_to_check=10385 ns`；再运行 `comparison_report/run_impl.tcl`，它会重新生成输入和权重 RAM 的综合结果，随后重新综合并布线。各阶段报告和日志与 B 同名，位于 C 的 `comparison_report/` 下。

## 5. 如何选择

- 如果目标是**单次计算尽快结束**，保留 A。它在 100 MHz 下约 5.265 µs，估算频率也略高。
- 如果后续层或其他模块需要腾出 DSP、BRAM 和逻辑资源，并且可接受约 10.385 µs 的单次时间，选 C。C 的资源节省幅度明显，100 MHz 时序仍通过。
- B 只作为隔离“改变路数”和“改变 RAM 布局”影响的实验记录；在这次测量中，C 的资源与时序均优于 B，完成时间相同。

真正的最终选择还需根据整套网络的 DSP/BRAM 预算和单帧时限确定。两个可用方案 A、C 的结果都已保存，可在系统目标明确后直接选择。当前尚未测量板上实际频率、外部数据传输时间与功耗。
